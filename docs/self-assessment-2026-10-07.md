# 본선 평가항목 자가 채점 (2026-10-07 기준)

평가 기준은 공지된 3개 항목(30+25+25=80점)으로 채점했다. 나머지 20점(발표 등)은 공지에 없어 비워 둔다.
근거는 저장소 코드와 10/6~10/7 실측치. 점수는 "지금 이 상태로 심사받으면" 기준의 보수적 자가 평가다.

| 항목 | 배점 | 자가 점수 | 한 줄 판단 |
| --- | --- | --- | --- |
| ① 결과물 완성도 | 30 | **24** | 한 바퀴가 실데이터 위에서 실제로 돈다. 배포·모바일 마감이 남았다 |
| ② AI·데이터 활용의 적절성 | 25 | **21** | AI 는 필요한 두 곳에만, 검증 루프와 안전장치가 있다. 평가 데이터가 적다 |
| ③ 문제 해결력·실무 적용 가능성 | 25 | **18** | 문제정의가 데이터로 입증되고 라우팅·개인정보 설계가 있다. 운영 주체·비용 수치가 비어 있다 |

## ① 결과물 완성도 — 24/30

**되는 것 (증거)**
| 기능 | 상태 | 확인 방법 |
| --- | --- | --- |
| 신고 폼: 사진 박스+미리보기, 글, 지도 탭 | 동작 | `/report`, 브라우저 실측 |
| Claude 1회 호출로 학교·종류·기관·위치확신도·요약 | 동작 | 모의 12건 종류/기관/학교 12/12·12/12·11/11 |
| 개인정보 마스킹(전화·차량번호·이름) | 동작 | 24건 요약·이유 누출 0 |
| 공무원 점검표: 탭·KPI·카드·확정/해결/기각 | 동작 | `/admin` |
| 좌표 보정 지도(클릭→저장→확신도 high) | 동작 | 브라우저 실측 |

| 시연 데이터 1분 재현 | 동작 | `npm run demo` |

**아직 아닌 것 (감점 요인)**
- 실제 도메인 배포 전(진행 중). 발표자료에는 캡처로 대체 가능(공지 2번).
- 모바일 화면 다듬기 미완. 와이어프레임 반영 전.
- 신고 입구는 폼뿐. 문자(MMS)·안전신문고 연계는 설계만.
- 공무원 인증이 비밀번호 1개(역할·기관별 계정 없음).
- 자동화 테스트 코드 없음(curl·브라우저 수동 검증).
- 월간 리포트는 버튼으로 생성(매월 자동 실행 없음).

## ② AI·데이터 활용의 적절성 — 21/25

**잘 쓴 곳**
- AI 는 두 지점에만: 신고 1건당 분류 1회, 학교당 월 1회 리포트. "많이"가 아니라 "제각각인 말을 구조로 바꾸는 곳"에만.
- AI 가 못 하게 한 것이 명확: 위험 판단 안 함, 표 밖 학교·기관은 서버가 거부, 확정 전 시민 비노출, 점수·순위 금지.
- 검증 루프: 정답 라벨 12건으로 정확도 측정 → v1 11/12 → 프롬프트 한 줄(v2) → 12/12. 종류 정의·기관 표는 안 건드림.
- 개인정보 3중 방어(전처리 마스킹·프롬프트·사후 검사), 누출 0.
- 데이터: 공공데이터 3종(학교·보호구역·사고다발) 적재. 정제 중 남양주 오매칭(108→40), 법정동 정규식 오류를 발견·수정.
- 제작 과정의 AI 활용도 유형별로 기록(docs/ai-usage-log.md 2부).

**약한 곳**
- 평가 데이터 12건은 팀이 만든 것. 실제 학부모 신고 문장은 없다.
- 사진 판독 실측은 4장.
- 공무원이 AI 제안을 고친 기록(PATCH)을 아직 개선에 쓰지 않는다.
- 월간 리포트의 "숫자 창작 금지"는 눈으로만 확인(자동 검증 없음).

## ③ 문제 해결력·실무 적용 가능성 — 18/25

**해결하는 것**
- 문제정의: 옥정·회천 새 학교는 사고 기록이 없어 "사고 지도"에 안 뜬다 → 사고다발지역 API 실측이 이를 보여준다(40교 중 2교만 해당). 학부모 신고를 첫 신호로 쓰는 설계가 데이터로 뒷받침된다.
- 신고 문턱 제거(종류 선택 불필요) + 담당 기관·법적 근거 자동 제안 → 공무원은 "현장에 갈지"만 판단. KPI "신고→첫 조치 중앙값"이 화면에 있다.
- 운영 흐름이 끊기지 않음: AI 실패도 직접 검토 큐로, 사람이 마지막 결정.
- 개인정보·보안 설계: 마스킹, 사진 미저장, 신고자·학원·가게 비노출, 확정 전 비공개, 서비스 키는 서버 전용, RLS.
- 비용 구조 예측 가능: 신고 1건 = 호출 1회.

**비어 있는 것**
- 운영 주체: 시민안전과 총괄 + 기관 표(6개)로 설계했지만 실제 기관 협의·업무 흐름 확인 없음.
- 비용: 호출 구조는 있으나 월 신고량 가정과 금액 산정이 없다(기획안에서 채울 것).
- 법적 근거 표(도로교통법 32·33조 등)는 전문가 검증 전.
- 문자·안전신문고 입구, 기관 간 이관, 처리 결과 회신 등 실제 민원 시스템과의 연결은 설계만.
- 접근성·다문화(다국어) 고려 없음.

## 본선 전 보완 우선순위 (점수 대비 효과 큰 순)
1. **배포 + 발표자료용 동작 캡처**(① 직접) — 신고→AI 제안→확정→지도 색 변경→진행 확인→리포트 6장면. 공지 2번: 캡처가 곧 평가 근거.
2. **운영 주체·비용 한 장**(③) — 월 신고 N건 가정, 호출 1회 토큰·금액, 담당 부서별 처리 흐름. Cowork 에서.
3. **실제 문장으로 평가 데이터 늘리기**(②) — 맘카페·민원 공개 글 유형을 참고한 20~30건, 정확도 재측정.
4. **모바일 화면 마감**(①) — 와이어프레임 반영, 시연 대본 리허설.
5. 공무원 수정 로그를 개선 데이터로 쓰는 구조 한 줄 설명(②).
