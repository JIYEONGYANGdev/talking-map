# AI 활용 기록

공모전 "AI 활용" 평가용. 두 관점으로 나눠 기록한다.
- **1부 — 기획 아이템 관점**: 이 서비스 자체가 AI 를 어디에, 왜, 어떤 안전장치와 함께 쓰는가. 시민·공무원에게 생기는 가치.
- **2부 — 개발 과정 관점**: 만드는 동안 AI(Claude Code·Cowork)가 사람 대신 해 준 일.

작업하면서 계속 추가한다. 항목마다 날짜를 적고, 측정값이 있으면 숫자를 남긴다.

# 1부. 서비스 안의 AI — 기획 아이템 관점

## 1. 시민 접점: 신고의 문턱을 없앤다
- **종류를 고르지 않아도 되는 신고 (설계)** 기존 민원 창구는 "불법주정차 / 도로 파손 / …" 중 하나를 신고자가 골라야 한다. 이 서비스는 사진 한 장과 평소 쓰는 말 한 줄만 받고, 종류·학교·담당 기관·위치 확신도·한 문장 요약을 AI 가 정리한다(`lib/ai.ts`, 신고 1건당 호출 1회). 학부모는 "뭐라고 분류해야 하지"를 고민하지 않는다.
- **제각각인 말을 구조로 (10/7 측정)** 모의 신고 12건(띄어쓰기 없는 문장, 비속어 없는 구어, 학교 약칭 "옥정초", 상대 위치 "정문에서 편의점 쪽 50m")을 종류 12/12, 기관 12/12, 학교 11/11 로 정리. 글만으로 학교를 알 수 없는 1건은 억지로 맞추지 않고 "학교명 확인 필요"로 남김 — 이것도 의도한 동작.
- **위치를 글에서 읽어낸다** "후문 쪽", "정문에서 50m" 같은 상대 위치를 기준 지점(anchorAddress)+상대 설명(relativeDesc)으로 뽑고, 지도에서 찍은 위치가 있으면 그것을 우선한다. 확신도(high/mid/low)를 같이 내서 공무원 화면에서 "위치 확인 필요"만 골라 보정하게 한다.
- **사진은 보이는 것만** evidence 필드는 "사진에서 실제로 보이는 것"만 적게 하고 추측을 금지한다. 사진 자체는 저장하지 않고 분류에만 쓴다(학부모 화면 비노출 원칙).
- **접수 즉시 되돌려주는 말** 접수 화면과 `/reports/:token` 에서 "AI 가 종류와 담당 기관을 정리했고, 공무원이 확인한 뒤 지도에 표시됩니다"를 보여줘 신고가 어디로 가는지 알게 한다. 실서비스에서는 이 링크가 회신 문자로 간다.

## 2. 공무원 업무: 분류·배정 시간을 없애고 판단에만 쓰게 한다
- **담당 기관 + 법적 근거까지 제안** 종류에 따라 양주시 교통/도로·시설/시민안전과, 양주경찰서, 교육지원청, 공사 주체 중 하나를 고르고, 기관 표의 법적 근거(도로교통법 제32조 등)를 붙인다. 공무원은 "어느 부서 소관인가"가 아니라 "현장에 나갈 것인가"만 판단한다. 지표: `/admin` 상단 "신고→첫 조치 중앙값".
- **한 문장 요약 + 고른 이유** 긴 신고 글 대신 요약 한 줄과 "왜 그 기관인지" 한 문장을 카드에 보여준다. 공무원은 원문을 다 읽지 않아도 된다(원문은 마스킹본으로 같이 보임).
- **AI 실패도 업무 흐름 안에** API 오류·분류 불가 시 신고는 그대로 남고 "AI 실패·직접 검토" 탭으로 간다. AI 가 멈춰도 민원이 사라지지 않는다.
- **같은 곳 신호 묶기** 확정된 신호 50m 안에 다른 확정·해결 신호가 있으면 "점검 우선"으로 색이 바뀐다(`lib/geo.ts`). AI 분류가 좌표를 갖게 해 주기 때문에 가능한 규칙.

## 3. 신뢰 장치: AI 가 넘지 못하게 한 선
- **AI 는 위험 여부를 판단하지 않는다** 종류·위치·담당 기관 정리만. "위험하다/아니다"와 현장 확인은 사람(공무원)이 한다. 프롬프트 규칙 5.
- **공무원 확정 전에는 시민에게 보이지 않는다** AI 결과는 `ai_proposed` 상태로 학부모에게 "검토 중"으로만 보이고, 지도에는 `confirmed` 이후만 표시. AI 오분류가 바로 공개되는 일이 없다.
- **표 밖의 값은 서버가 거부한다** 학교는 `data/schools.json`(양주시 초등 40교), 기관은 `data/agencies.json` 표 밖이면 null 로 바꾼다. AI 가 존재하지 않는 학교·기관·법 조항을 만들어내도 시스템에 들어오지 못한다(`lib/ai.ts` 하단 검증 + tool use strict 스키마).
- **개인정보 3중 방어** ① 이름·전화·차량번호를 AI 전송 전에 마스킹(`lib/mask.ts`) ② 프롬프트에서 요약에 옮기지 말라고 지시 ③ 결과를 자동 검사. 10/7 측정 24건(v1+v2) 누출 0. 신고자·학원·가게 이름은 시민 화면에 안 나온다.
- **점수·순위를 매기지 않는다** AI 로 쉽게 만들 수 있는 "학교별 위험 점수"를 일부러 만들지 않는다. 학교에 낙인이 찍히고 신고가 줄어드는 역효과를 막기 위해 변화(점검 우선/처리 중/고쳐짐)만 보여준다. 월간 리포트 프롬프트에도 "점수·순위·다른 학교와 비교 금지".

## 4. 학부모 소통: 숫자를 쉬운 말로
- **월간 리포트 자동 작성** 학교별로 그 달의 신호·해결 건수를 입력하면 AI 가 3문단 이내 존댓말로 쓴다. "입력에 없는 숫자를 만들지 않는다", "고쳐진 게 없으면 사실대로" 를 규칙으로 못 박았다. 마지막 문장은 참여 권유 한 줄.
- **빈 상태도 메시지** 사고다발지역 API 결과 양주시 40교 중 2교만 해당(10/7 적재). 나머지 학교에는 "아직 사고 지도에 없습니다 — 신고가 첫 신호입니다"를 보여준다. 사고 기록이 없는 새 동네의 데이터 공백을 학부모 신고로 메운다는 기획의 출발점을 화면에 그대로 둔다.

## 5. 측정과 개선: AI 를 운영 가능한 부품으로
- **정확도를 숫자로 재는 루프** `data/mock-reports.json` 에 정답 라벨을 붙여 두고 `npm run seed` 로 종류/기관/학교 일치율과 PII 누출을 자동 측정. 프롬프트는 `prompts/vN.ts` 로 버전을 올리며 바꾼다. 10/7: v1 → v2 로 11/12 → 12/12.
- **바꾸는 범위를 좁게** 종류 정의나 기관 표를 늘리지 않고 라우팅 규칙 한 줄만 추가해 개선. "정책 판단(킥보드 방치는 어느 부서 소관인가)"은 사람이, "그 판단을 모델이 따르게 하는 일"은 프롬프트가.
- **운영 데이터가 곧 학습 데이터** 공무원이 카드에서 종류·기관·학교·좌표를 고치는 PATCH 기록은 AI 제안 vs 사람 확정의 차이 그 자체다. 이것을 모아 프롬프트 개선과 모의 신고 세트 보강에 쓸 수 있다(다음 단계).
- **호출 구조가 단순** 신고 1건 = Claude 1회(사진 포함), 학교 1곳 = 월 1회 리포트. 비용·지연을 예측할 수 있다(비용 산정은 Cowork 세션 몫).

## 6. 확장 아이디어 (AI 가 있어서 가능한 다음 단계)
- **되묻기** 학교·위치를 알 수 없는 신고(모의 9번 유형)에 "어느 학교 근처인가요?"를 자동 회신 문자로 묻기. 지금은 공무원 직접 검토 큐로만 간다.
- **문자(MMS)·안전신문고 입구** 폼 대신 시장 직통 문자나 안전신문고 접수를 그대로 받아 같은 분류기로 흘리기. 분류 로직은 입구와 분리되어 있어(`POST /api/reports` JSON/multipart 둘 다) 입구만 붙이면 된다.
- **유사 신고 자동 묶기** 지금은 50m 거리 규칙. 요약 문장의 의미 유사도로 "같은 문제의 반복 신고"를 묶으면 공무원 카드 수가 줄어든다.
- **다국어 신고** 다문화 가정 학부모의 외국어 신고도 같은 호출에서 한국어 요약으로 정리 가능(프롬프트 한 줄).
- **처리 결과 회신문 초안** 고쳐짐 처리 시 학부모에게 보낼 문자 초안을 AI 가 쓰고 공무원이 승인.

# 2부. 개발 과정의 AI — 개발 생산성 관점

만드는 동안 Claude Code(코드)·Cowork(기획·문서)가 사람 대신 해 준 일. 형식: 무슨 일 → AI 가 한 일 → 사람이 집중할 수 있었던 것.

## 유형 A. 데이터 적재·정제에서 오류를 빠르게 발견·수정
- **남양주시 오매칭 (10/7)** 공공데이터 학교 CSV를 "양주시" 문자열로 거르자 108교가 나왔다. AI가 목록을 훑어 남양주시 학교가 섞인 것을 즉시 발견, `(?<!남)양주시` 로 수정 → 40교. 사람은 "양주시 초등학교가 40개"라는 결과 검증에만 집중.
- **한글 뒤 `\b` 정규식 버그 (10/7)** 법정동 추출 정규식이 한글 다음의 `\b`를 경계로 보지 않아 전부 폴백 분기로 흘렀다. 분류 결과가 도로명 규칙과 똑같다는 점에서 AI가 역추적해 lookahead `(?=\s|$)` 로 교체.
- **권역 분류 기준 재설계 (10/7)** 도로명 주소 의존(옥정동로·회천중앙로 등)으로 회암초·율정초가 오분류되던 것을 발견, 지번주소의 법정동 → 행정동(옥정1·2동 / 회천1~4동 / 그 외) 매핑으로 바꿈. 40교 전체 주소를 표로 대조해 확인.
- **인코딩 자동 판별** CP949 CSV를 `file`/`iconv` 로 판별·변환하고 헤더가 스크립트의 컬럼 후보와 맞는지 먼저 확인.
- **모의 신고 데이터 일괄 교체** 임시 학교 3개 → 실제 학교 ID 로 12건 텍스트·라벨 치환(치환 순서까지 고려: "옥정A초등학교" 먼저, "옥정A초" 나중).

## 유형 B. 개발 환경 문제의 근본 원인 진단
- **Node 14 vs 22 (10/6~7)** `npm install` 이 lockfile 을 v1 으로 바꿔 5,000줄 diff 를 만든 원인이 시스템 Node 14/npm 6 임을 로그로 특정. nvm Node 22 로 재설치해 lockfile 을 커밋본과 동일하게 복구.
- **Turbopack 패닉 (10/6)** 페이지 500 의 원인이 `internal/modules/cjs/loader.js` 경로(= Node 14)로 뜬 PostCSS 워커임을 패닉 로그에서 읽어냄. PATH 수정 후에도 재현되자 `.next` 영속 캐시에 실패가 남은 것을 의심해 삭제 → 해결.
- **`.env.local` 미로딩 (10/7)** `tsx` 직접 실행 스크립트는 Next 와 달리 .env 를 읽지 않음을 설명하고 `process.loadEnvFile` 로 해결.
- **이미 열려 있던 터미널의 PATH** "zsh: command not found: nvm" 이 설정 파일 수정 전에 열린 세션 때문임을 npm 디버그 로그의 PATH 로 증명하고 새 탭에서 dev 서버 재기동.

## 유형 C. 외부 API 연동을 문서 없이 빠르게
- **도로교통공단 사고다발지역 API (10/6~7)** 기술문서(hwp) 없이 엔드포인트 후보를 키 없이 호출해 "미등록 서비스키"(경로 존재) vs "서비스 없음" 응답으로 경로를 확정. 파라미터가 법정동 코드(경기 41, 양주 630)임을 검색으로 확인. 응답 스키마는 방어적으로 파싱(items.item 이 객체/배열, 숫자가 문자열).
- **연도 범위 확장** 기본 2020~2024 로 적재한 뒤 2025 자료를 다른 연도·시군구 조합 프로브로 발견, 범위를 "작년까지"로 수정 → 양주시 1건→2건.

## 유형 D. Claude API 최신 규칙 준수 (모델 호환성)
- **강제 tool_choice 거부 (10/6)** Sonnet 5.5 는 `tool_choice:{type:"tool"}` 을 400 으로 거부. 최신 API 레퍼런스를 참조해 `auto` + `strict` 스키마 + 시스템 프롬프트 지시로 대체. 적응형 사고 토큰을 고려해 max_tokens 상향, `refusal` stop_reason 처리 추가.
- **워크스페이스 헤더** 조직 범위 키의 400 메시지를 읽고 `ANTHROPIC_WORKSPACE_ID` → `anthropic-workspace-id` 헤더 지원 추가(이후 사용자가 워크스페이스 키로 교체).

## 유형 E. 기존 코드를 재사용한 UI 구현
- **공무원 좌표 보정 지도 (10/6)** 신고 폼의 `SchoolMap onPick/picked` 를 그대로 재사용해 /admin 카드에 접이식 지도 + "이 위치로 저장"(PATCH lat/lng) 구현. low 확신도는 배지 + 자동 펼침. Leaflet 인스턴스 폭증을 막기 위해 펼쳤을 때만 렌더.
- **사고다발지역 레이어 + 빈 상태** 지도 레이어(크기 ∝ 사고 건수)와 "아직 사고 지도에 없습니다 — 신고가 첫 신호입니다" 문구를 같이 설계. 빈 상태가 곧 문제정의라는 기획 의도를 코드로 옮김.

## 유형 F. 검증 자동화 (사람 대신 한 바퀴 돌려보기)
- **curl 한 바퀴** 신고 → 마스킹 확인 → 로그인 → PATCH/confirm → 학부모 지도 API → 진행 확인 페이지를 스크립트로 반복 검증.
- **브라우저 자동 조작** 내장 브라우저로 /admin 지도 클릭 → 저장 → 확신도 high 전환까지 실제 클릭으로 확인. 콘솔 에러·서버 로그 동시 확인.
- **모의 신고 12건 정확도 측정 (10/7)** `npm run seed` 후 종류/기관/학교 일치율과 PII(전화·차량번호·이름) 누출을 자동 대조. v1: 11/12·11/12·11/11, 누출 0.
