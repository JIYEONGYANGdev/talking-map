# AI 활용 기록 (개발 과정)

공모전 "AI 활용" 평가용. 이 프로젝트에서 AI(Claude Code·Cowork)가 **무엇을 어떻게** 도왔는지 유형별로 기록한다.
작업하면서 계속 추가한다. 각 항목은 "무슨 일이 있었나 → AI가 한 일 → 사람이 집중할 수 있었던 것" 순서.

## 유형 A. 데이터 적재·정제에서 오류를 빠르게 발견·수정
- **남양주시 오매칭 (10/7)** 공공데이터 학교 CSV를 "양주시" 문자열로 거르자 108교가 나왔다. AI가 목록을 훑어 남양주시 학교가 섞인 것을 즉시 발견, `(?<!남)양주시` 로 수정 → 40교. 사람은 "양주시 초등학교가 40개"라는 결과 검증에만 집중.
- **한글 뒤 `\b` 정규식 버그 (10/7)** 법정동 추출 정규식이 한글 다음의 `\b`를 경계로 보지 않아 전부 폴백 분기로 흘렀다. 분류 결과가 도로명 규칙과 똑같다는 점에서 AI가 역추적해 lookahead `(?=\s|$)` 로 교체.
- **권역 분류 기준 재설계 (10/7)** 도로명 주소 의존(옥정동로·회천중앙로 등)으로 회암초·율정초가 오분류되던 것을 발견, 지번주소의 법정동 → 행정동(옥정1·2동 / 회천1~4동 / 그 외) 매핑으로 바꿈. 40교 전체 주소를 표로 대조해 확인.
- **인코딩 자동 판별** CP949 CSV를 `file`/`iconv` 로 판별·변환하고 헤더가 스크립트의 컬럼 후보와 맞는지 먼저 확인.
- **모의 신고 데이터 일괄 교체** 임시 학교 3개 → 실제 학교 ID 로 12건 텍스트·라벨 치환(치환 순서까지 고려: "옥정A초등학교" 먼저, "옥정A초" 나중).

## 유형 B. 개발 환경 문제의 근본 원인 진단
- **Node 14 vs 22 (10/6~7)** `npm install` 이 lockfile 을 v1 으로 바꿔 5,000줄 diff 를 만든 원인이 시스템 Node 14/npm 6 임을 로그로 특정. nvm Node 22 로 재설치해 lockfile 을 커밋본과 동일하게 복구.
- **Turbopack 패닉 (10/6)** 페이지 500 의 원인이 `internal/modules/cjs/loader.js` 경로(= Node 14)로 뜬 PostCSS 워커임을 패닉 로그에서 읽어냄. PATH 수정 후에도 재현되자 `.next` 영속 캐시에 실패가 남은 것을 의심해 삭제 → 해결.
- **`.env.local` 미로딩 (10/7)** `tsx` 직접 실행 스크립트는 Next 와 달리 .env 를 읽지 않음을 설명하고 `process.loadEnvFile` 로 해결.
- **이미 열려 있던 터미널의 PATH** "zsh: command not found: nvm" 이 설정 파일 수정 전에 열린 세션 때문임을 npm 디버그 로그의 PATH 로 증명하고 새 탭에서 dev 서버 재기동.

## 유형 C. 외부 API 연동을 문서 없이 빠르게
- **도로교통공단 사고다발지역 API (10/6~7)** 기술문서(hwp) 없이 엔드포인트 후보를 키 없이 호출해 "미등록 서비스키"(경로 존재) vs "서비스 없음" 응답으로 경로를 확정. 파라미터가 법정동 코드(경기 41, 양주 630)임을 검색으로 확인. 응답 스키마는 방어적으로 파싱(items.item 이 객체/배열, 숫자가 문자열).
- **연도 범위 확장** 기본 2020~2024 로 적재한 뒤 2025 자료를 다른 연도·시군구 조합 프로브로 발견, 범위를 "작년까지"로 수정 → 양주시 1건→2건.

## 유형 D. Claude API 최신 규칙 준수 (모델 호환성)
- **강제 tool_choice 거부 (10/6)** Sonnet 5.5 는 `tool_choice:{type:"tool"}` 을 400 으로 거부. 최신 API 레퍼런스를 참조해 `auto` + `strict` 스키마 + 시스템 프롬프트 지시로 대체. 적응형 사고 토큰을 고려해 max_tokens 상향, `refusal` stop_reason 처리 추가.
- **워크스페이스 헤더** 조직 범위 키의 400 메시지를 읽고 `ANTHROPIC_WORKSPACE_ID` → `anthropic-workspace-id` 헤더 지원 추가(이후 사용자가 워크스페이스 키로 교체).

## 유형 E. 기존 코드를 재사용한 UI 구현
- **공무원 좌표 보정 지도 (10/6)** 신고 폼의 `SchoolMap onPick/picked` 를 그대로 재사용해 /admin 카드에 접이식 지도 + "이 위치로 저장"(PATCH lat/lng) 구현. low 확신도는 배지 + 자동 펼침. Leaflet 인스턴스 폭증을 막기 위해 펼쳤을 때만 렌더.
- **사고다발지역 레이어 + 빈 상태** 지도 레이어(크기 ∝ 사고 건수)와 "아직 사고 지도에 없습니다 — 신고가 첫 신호입니다" 문구를 같이 설계. 빈 상태가 곧 문제정의라는 기획 의도를 코드로 옮김.

## 유형 F. 검증 자동화 (사람 대신 한 바퀴 돌려보기)
- **curl 한 바퀴** 신고 → 마스킹 확인 → 로그인 → PATCH/confirm → 학부모 지도 API → 진행 확인 페이지를 스크립트로 반복 검증.
- **브라우저 자동 조작** 내장 브라우저로 /admin 지도 클릭 → 저장 → 확신도 high 전환까지 실제 클릭으로 확인. 콘솔 에러·서버 로그 동시 확인.
- **모의 신고 12건 정확도 측정 (10/7)** `npm run seed` 후 종류/기관/학교 일치율과 PII(전화·차량번호·이름) 누출을 자동 대조. v1: 11/12·11/12·11/11, 누출 0.
- **프롬프트 v1→v2 개선 루프 (10/7)** 유일한 불일치(보도에 쓰러진 킥보드 → "기타")를 입력·AI 출력·정답 라벨 나란히 보고, 종류 정의나 기관 표는 건드리지 않은 채 라우팅 규칙 한 줄(3-1)만 추가한 v2 로 재측정 → 12/12·12/12·11/11. 사람은 "킥보드 방치를 어느 부서가 맡을지"라는 정책 판단에만 관여.

## 유형 G. 서비스 안의 AI (제품 기능으로서의 AI)
- 신고 1건당 Claude 1회 호출로 학교 연결·종류·담당기관·위치 확신도·요약을 **tool use JSON 스키마**로 구조화.
- **AI 가 만들어낼 수 없게 하는 설계**: 학교는 `data/schools.json`, 기관은 `data/agencies.json` 표 밖이면 서버가 거부. 위험 여부는 판단하지 않고 정리만.
- **개인정보**: 이름·전화·차량번호를 AI 전송 전 마스킹(`lib/mask.ts`), 프롬프트에서도 요약에 옮기지 말라고 지시, 결과를 자동 검사.
- **사람이 마지막**: AI 결과는 공무원 확정 전엔 학부모에게 "검토 중"으로만, 지도에는 확정 이후만 표시. AI 실패 시에도 신고는 남기고 직접 검토 큐로.
- 월간 리포트 생성(점수·순위 없이 변화만 쓰도록 제약).

## 유형 H. 문서화·인수인계
- CLAUDE.md 에 설계 원칙·한 바퀴·남은 일·환경 규칙을 유지해 어떤 세션이 열려도 같은 맥락에서 시작. Cowork(기획·발표) ↔ Code 탭(코드) 분업 규칙.
- 커밋 메시지에 "왜"를 남김(예: 왜 auto tool_choice 인지, 왜 법정동 기준인지).
